BLOCKER Product and scope / Verification — "Assumptions" + "Apply fine-pointer hover/focus visibility and coarse-pointer always-kebab/no-arrow rules" — on coarse pointers the previous/next buttons are `display:none` and swipe is the only navigation path, and dots are explicitly passive; there is no accessible or non-gesture route to slides B/C. Screen-reader, switch-access, and any user whose gesture is intercepted by assistive tech can never see the B/C mockups on touch devices, which defeats the plan's stated value ("inspect all generated mockup directions"), and `display:none` also removes the buttons from the accessibility tree so no test in the matrix catches it. Fix: keep the previous/next buttons in the DOM on coarse pointers (visually hidden but AT-reachable, or shown as small persistent controls) and add an `aria-live="polite"` slide announcement ("Option B of 3"); assert AT reachability in the touch Playwright case rather than asserting `display:none`.

MAJOR Runtime and change impact "Failure And Recovery" / "Add touch swipe with vertical-scroll discrimination and one-shot link-navigation suppression" — a one-shot suppression flag set on a qualified swipe has no expiry or reset condition; a swipe that ends outside the link, is followed by scrolling, or produces no synthetic click leaves the flag armed. The next genuine tap on that card is swallowed and the project does not open, and the user has no feedback explaining it. Fix: scope suppression to the click event immediately following the gesture (clear it in a `setTimeout(0)`/next-tick or on the subsequent `touchstart`), and add a test that swipes, waits, then taps and asserts navigation succeeds.

MAJOR Runtime and change impact "Ownership, Scope, And Lifetime" / plan step "prop-change clamping" — "State resets/clamps when its preview list changes" is unspecified as to what "changes" means; the dashboard re-renders on `router.refresh()` after Rename/Delete, producing a new array identity with identical content. If the clamp keys on array/prop identity, every rename silently snaps every card back to slide A while the user is mid-inspection. Fix: key the reset on a stable content signature (preview count + ordered URLs or labels), not object identity, and add a test that re-renders with an equal-but-new array and asserts the active index is preserved.

MAJOR Premises "Assumptions" (partial rows are historical) — mockup options are generated sequentially A/B/C (see docs/systems/dev-tasks-and-troubleshooting.md, 790s timeout), so the newest row is routinely partial *while generation is in flight*, not only for legacy data. A server-rendered dashboard card will show one dot and one slide for an actively generating project and never update without a manual reload, and the plan adds no in-progress affordance while explicitly ruling out polling/subscriptions. Fix: distinguish "partial because still generating" from "partial historical" using the mockups row status / `generation_queue_items`, and either render a pending indicator for the missing slides or state explicitly that a reload is required; I would need src/app/(dashboard)/projects/page.tsx and the mockups row shape to confirm which status field is available.

MAJOR Verification "Real Chrome: existing authenticated projects only, no new project/generation/credits" — the three-slide carousel, dot count, middle-slide state, and bounded arrow behavior can only be observed if an existing account project already has valid A, B, and C options; the plan asserts no precondition and forbids generating one. MAJOR Runtime and change impact "Boundary And Cache Semantics" — the claim that "existing browser/private proxy caching stays authoritative" is unverified; if `/api/mockups/image` responds with `Cache-Control: no-store`/`private, max-age=0` (typical for an auth-gated media proxy), active-slide-only rendering means every A→B→A traversal re-downloads a full-resolution image through an authenticated round trip, so the chosen design trades one-time fan-out for unbounded repeat traffic and a visible blank media panel on each step back. Fix: read src/app/api/mockups/image/route.ts and confirm the response cache headers before committing to unmount-on-navigate; if responses are uncacheable, keep visited slides mounted (hidden) rather than unmounting them, and add the header assertion to the risk matrix instead of assuming it.

MAJOR Verification "Risk-Matched Verification" (Touch controls) and "Playwright touch context" — `(hover: none) and (pointer: coarse)` is a media-feature query; Playwright's `hasTouch`/`isMobile` context options do not reliably drive the `hover`/`pointer` media features in Chromium without an explicit CDP `Emulation.setEmulatedMedia` features call. As written the touch suite will either fail for the wrong reason or, if the assertion is written loosely, pass without the coarse-pointer rules ever being exercised, so the single most requested behavior ships unverified. Fix: emulate the media features explicitly via CDP (or a test-only forced class) in the touch project setup, and add a self-check assertion that `matchMedia('(pointer: coarse)').matches` is true before running the visibility assertions.

MINOR Premises "Assumptions" (no fallback to an older row) — if the newest mockup row is malformed or its options fail path validation, the card drops to the empty state even when an older row holds valid, previously-visible previews; that is a user-visible regression introduced by this change, not preserved behavior.
