MAJOR premises "Recommended First Step" / Test Strategy (Node tests: "new media/details render contract", "378px media/122px details contract") — Node/tsx unit tests render to no layout engine, so a "red" geometry test can only assert class strings or inline style values, which pass regardless of whether flex shrink, a parent `overflow`, or the new overlay actually produce 378/122. The first step therefore produces tests that cannot fail when the change is wrong, and the only real geometry signal is deferred to the last Playwright/Chrome step. Fix: drop geometry from the Node suite (keep derivation/slide-count/kebab contracts there), and make the red-first step a Playwright bounding-box spec against the current card.

MAJOR verification Test Strategy → "Playwright touch context: first assert `matchMedia('(pointer: coarse)').matches`" — the self-check asserts a different media query than the CSS branch under test (`(hover: none) and (any-hover: none)`); Chromium touch emulation on a machine with a real pointer can report `pointer: coarse` while `any-hover: hover` remains true. The suite would either fail for an emulation reason unrelated to the code or, if the assertions are written loosely, pass while the coarse-pointer rule was never exercised. Fix: self-check the exact query used in CSS, `matchMedia('(hover: none) and (any-hover: none)').matches`, and assert it inside the same page context as the arrow-visibility assertions.

MAJOR runtime "Selected — one semantic control set with capability-driven CSS presentation" / Failure And Recovery — arrows stay in the accessibility tree but are hidden with `opacity: 0` plus `pointer-events: none` on coarse-pointer devices, where there is no hover to re-enable them. A VoiceOver/TalkBack user who reaches the "Next" button and double-taps produces a synthetic click at the element's coordinates that passes through the pointer-events-disabled arrow to the full-card link, opening the workspace instead of changing slides — the exact failure the plan claims sibling controls prevent. Fix: on coarse pointers render arrows with a visually-hidden clip technique that keeps `pointer-events: auto` and a real hit box, and reserve the opacity/pointer-events-none treatment for the fine-pointer hover state only.

MAJOR runtime "Add card-local carousel index, roving sibling dot buttons, previous/next pointer controls" — dots are always visible and arrows are positioned at media center, so their containers overlay the media panel while being DOM siblings of the card link; the plan never states that these overlay wrappers carry `pointer-events: none` with the buttons re-enabling it. If the dot wrapper spans the media width, a horizontal strip of the card stops opening the project on both desktop and touch, and Playwright "URL stays /projects" assertions will not catch it because they only click controls. Fix: specify `pointer-events: none` on every overlay wrapper with `pointer-events: auto` on the buttons, and add a Playwright assertion that clicking the media area beside a dot and beside an arrow navigates to the project.

MAJOR runtime "Desktop first slide shows Next only, middle slides show Previous and Next, last slide shows Previous only" — unmounting the arrow the user just activated destroys the focused/hovered element: clicking Next into the last slide moves focus to `document.body`, which collapses `focus-within` and hides the remaining controls, and a keyboard user who reached the arrow loses their place entirely. Users must re-hover to continue backward navigation on every card they browse to the end. Fix: keep both arrows mounted for the card's lifetime and mark the unavailable direction `aria-disabled` (or `disabled`) rather than removing it, and assert focus stays on the arrow after reaching a bound.

MAJOR product Plan → "Rebuild thumbnail/details to Figma geometry: … 122px text area, title/date row, clipped description" — the plan never enumerates what the current details area renders (the header notes the old assumption was 160.6px), so a ~39px reduction plus the kebab's removal from the title row silently drops or clips whatever else lives there (status/generation indicator, secondary metadata). If the card currently surfaces generation or empty-state affordances in the details block, they disappear without a decision being recorded. Fix: before implementation, inventory the current details subtree in the dashboard card component (I would need `src/components/**/dashboard-project-card.tsx` and the projects page that renders it) and list each existing element as kept, moved, or intentionally removed.

MAJOR runtime Failure And Recovery → "A failed active image renders the existing fallback" / "Visited/failed sets are keyed by label+URL" — failures are sticky for the card's lifetime with no retry path, and `/api/mockups/image` is an authenticated proxy, so one expired session or transient 5xx permanently marks slides broken while the page stays mounted; a user who re-authenticates in another tab still sees broken slides with no way to retry short of a full reload. Fix: allow a failed slide to re-attempt on the next explicit navigation to it (e.g., re-mount with a cache-busting attempt counter), and cover "image 500 then navigate away and back recovers" in the Node/Playwright suite.

MAJOR premises Plan → "Add touch swipe with vertical-scroll discrimination and gesture-scoped link-navigation suppression" — the plan never says which subtree owns the touch listeners and `touch-action: pan-y`. If they sit only on the media panel, swipes started over the title/description do nothing (touch users get no arrows, so the only discoverable gesture silently fails on ~25% of the card); if they sit on the whole card, `touch-action: pan-y` and suppression must cover the details area and the kebab's hit region too. Fix: state that the gesture surface is the media panel only, size the swipe target to it, and add a touch test asserting a horizontal swipe over the details block scrolls/does nothing without breaking a later tap.

MINOR runtime "Selected — demand-load then retain visited slides" / Performance proxy — the plan does not say whether slides render through `next/image` or a raw `<img>`, nor what `loading`/`sizes` values the non-active slides get. If the existing card uses `next/image`, three mounted proxy URLs multiply optimizer work and the "exactly one request per newly visited slide" assertion becomes flaky for below-the-fold cards under lazy loading. Fix: pin the element type and loading attributes in the plan, and scope the request-count assertion to a card scrolled into view with lazy loading accounted for.

MINOR product "Selected — one semantic control set …" / Test Strategy — every card gets its own polite live region and its controls share generic names ("Next", "Option A"); on a grid of many projects a screen-reader user hears position updates with no project context and cannot distinguish one card's controls from another's, and the roving dot focus move plus the live status double-announce each navigation. Fix: include the project name in the accessible names/live text via `aria-label`, and choose either the focus move or the live region as the announcement source, not both.

MINOR product Plan → "unconditional vertical kebab placement" — the kebab becomes overlay chrome on a white media surface that renders arbitrary light mockup imagery, and on touch it is always visible; the plan specifies placement (20px inset) but no backing treatment, so the icon can sit invisible over pale mockups. Fix: specify a contrast-preserving chip/scrim behind the kebab and capture evidence over a light-dominant mockup.

MINOR verification Risk-Matched Verification → "Touch controls violate request or AT access | … visual arrows absent" — arrows are only visually hidden, so Playwright visibility helpers will report them present; the acceptance threshold as written is untestable by the obvious method and invites either a false failure or a loosened assertion. Fix: state the assertion as a computed-style check (opacity/clip and hit-testing at the arrow's coordinates resolving to the link or media, not the button).
