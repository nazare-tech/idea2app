MAJOR premises D2 / Assumptions “Everywhere” — The inventory is limited to consumers of one logo constant plus favicon and `CompassMark`; it does not establish that no direct SVG imports, metadata/manifest icons, or other rendered wordmarks use the retired mark. A partial rollout will leave conflicting brand marks in user-visible routes or installed-browser chrome. Fix: add an explicit repository-wide inventory and acceptance list covering direct asset references, metadata/manifest/favicon declarations, and all text/SVG wordmark renderers before choosing the in-place swap.

MAJOR runtime and change impact D2 / Phase 1 — Replacing `public/maker-compass-logo.svg` and `src/app/favicon.ico` at stable URLs has no cache-busting strategy; acknowledging that stale favicon “self-heals” does not bound how long returning users receive the old brand, and the same risk applies to the logo if static/CDN caching is enabled. Fix: use versioned asset URLs (and update every declared metadata/manifest reference) or explicitly verify and configure cache invalidation for the deployment platform.

MAJOR verification and rollback Rollback — A git revert cannot reliably roll back static assets already cached by browsers/CDNs at unchanged URLs, so rollback can leave users with a mixed old/new brand even after code rollback. Fix: define deploy-cache purge/versioned-asset rollback steps and verify both forward and rollback asset resolution in a production-like cache path.

MAJOR architecture and reuse D3 / Phase 2 step 6 — The plan declares a lucide-compatible icon module based only on `size`, `className`, and `strokeWidth`, without proving that the ten existing call sites use no other Lucide/SVG props, `ref`, accessibility behavior, or icon-specific geometry assumptions. Fix: inventory each target call site and define the component type as the actual Lucide/SVG prop contract, with a compatibility test for all props used; name the exact source files needed to confirm this.

MINOR verification and rollback Phase 4 / Test strategy — The icon smoke test verifies only generic SVG attributes; it would pass if an icon’s path is the wrong brand glyph, if a swapped call site still renders Lucide, or if the brand source geometry is malformed.
