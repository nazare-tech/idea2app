MAJOR premises docs/plans/dashboard-project-card-carousel-redesign-plan.md — "Assumptions"/"Failure And Recovery" — the plan specifies kebab placement only as a "media-panel vertical kebab" and never says where the kebab lives when a project has zero valid previews (the common case for new/pre-generation projects) or when the active image fails and the fallback surface renders. If the kebab is positioned relative to carousel chrome that only exists when previews exist, rename/delete becomes unreachable on the majority of dashboard cards, and on touch that is the only project menu. Fix: specify kebab as unconditional media-panel-overlay chrome independent of preview count, and add a test asserting kebab presence on a zero-preview card at both pointer capabilities.

MAJOR product docs/plans/dashboard-project-card-carousel-redesign-plan.md — "Assumptions" (dots are passive indicators) — dots sit inside the full-card link's hit area, so a user who clicks a dot to jump slides instead opens the workspace; on touch, where arrows are absent, dots are the only visible position affordance and are the most likely tap target. Users lose their place in the dashboard on a click they intended as carousel navigation. Fix: render dots as sibling elements outside the link with `pointer-events: none`, or make them real sibling buttons with labels (which also fixes coarse-pointer keyboard/AT navigation without SR-only duplicates).

MAJOR premises "Cross-Model Plan Evaluation" (rejection of partial canonical rows) — the argument that canonical rows always contain A/B/C rests only on `/api/mockups/finalize` requiring three labels, but the doc headers list `PATCH /api/mockups` row updates and `/api/mockups/generate-option`; either path can rewrite a canonical row's content after finalize. If single-option regeneration mutates the canonical row, "historical compatibility case" is actually a live path and the carousel silently drops to one slide on freshly regenerated projects. Fix: read `src/app/api/mockups/route.ts` and `src/app/api/mockups/generate-option/route.ts` to confirm post-finalize write shape, and state the confirmed invariant in Assumptions rather than deriving it from finalize alone.

MAJOR runtime "Failure And Recovery" (500ms suppression window) — suppressing link navigation with a wall-clock timer is racy in both directions: a synthesized click delayed past 500ms (slow device, momentum, delayed compositor) still opens the project after a swipe, and a deliberate tap inside the window is swallowed. The failure is user-visible and non-deterministic, so the Playwright "delayed tap opens the project" assertion will pass while real devices still misfire. Fix: set a `swipeConsumed` flag on qualifying touchmove, check and clear it in the click handler, and reset it on the next `touchstart` — no timer.

MAJOR architecture "Architecture Improvement Opportunities" (capability-driven CSS) + "Assumptions" (SR-only coarse controls) — the plan never states whether coarse-pointer detection is CSS media query or JS `matchMedia`. CSS-only means the SR-only prev/next duplicates exist in the accessibility tree on desktop too (unless `display:none`, which removes them from AT on touch and defeats the point), giving every keyboard user two sets of prev/next per card; JS-only means an SSR/hydration mismatch on the dashboard's server-rendered cards. Fix: choose one rendering of prev/next controls that is always in the DOM and always AT-reachable, and vary only visual presentation (visually-hidden vs visible) via the media query — drop the duplicate control set.

MAJOR verification "Test Strategy" (Playwright touch context) — Playwright's `page.touchscreen` API supports `tap` only; a horizontal swipe requires manually dispatched `touchstart`/`touchmove`/`touchend` sequences or CDP `Input.dispatchTouchEvent`, and `mouse.move` will not fire the touch handlers at all. Written as specified, the swipe tests will either be silently rewritten to mouse drags (testing a code path that does not exist on touch) or blocked mid-implementation. Fix: name the exact gesture mechanism in the plan and add a self-check that the swipe test observed a `touchmove` handler firing, mirroring the existing coarse-pointer self-check.

MAJOR runtime "Plan" / "Runtime And Change-Impact Analysis" — nothing addresses dashboard cards for projects whose mockups are still generating via the Generate All queue (`generation_queue_items`, `generate-all-store.ts`), where preview arrays can arrive or change after mount. The plan mentions "stable-signature prop-change clamping" but never says whether the dashboard refreshes/polls, so a card can sit in the empty state after generation completes, or jump slides on refresh. Fix: state the dashboard's current refresh mechanism (needs `src/app/(dashboard)/projects/page.tsx`), and define the transition from zero-preview to N-preview explicitly, including index reset to 0.

MINOR verification "Test Strategy" (Real Chrome) — making the primary real-flow evidence conditional on finding an existing project with three valid options, with "report the evidence blocker" as the only fallback, means the task can stall with all code written and no UI evidence, and per docs/operating-system/ui-verification.md fresh-project generation is opt-in. Fix: define graded evidence up front — a 2-option project validates bounded arrows and dot count, a 0-option project validates empty-state kebab — and reserve the blocker path for the case where no project has any valid option.

MINOR verification "Risk-Matched Verification" / "Performance proxy" — counting mounted `<img>` elements does not measure request fan-out: a mounted-but-hidden image still fetches, and the acceptance threshold as written would pass even if three requests fired. Fix: assert against `page.on('request')` counts filtered to `/api/mockups/image`, not DOM node counts.

MINOR runtime "Risk-Matched Verification" (Figma geometry drift) — asserting exact bounding boxes (500/378/122/24/20/32px) against a responsive grid will be flaky from sub-pixel layout and web-font metrics (Hanken Grotesk loads async), and 122px of details holding title, date row, and description depends on font load timing. Fix: assert heights with ±1px tolerance after `document.fonts.ready`, assert the clipped description by overflow/line-clamp rather than by measured height, and do not assert card width.

MINOR product "Plan" (hover/focus visibility) — adding kebab + previous + next as focusable siblings raises tab stops per card from 2 to 4, so keyboard traversal of a full dashboard roughly doubles before reaching any project. The plan never mentions this cost or any skip affordance. Fix: keep carousel controls out of the default tab order and expose them via the card's roving/`focus-within` group, or accept the cost explicitly in Assumptions so it is a decision rather than a side effect.

MINOR runtime "Boundary And Cache Semantics" (aria-live) — a polite live region rendered per card means N live regions on the dashboard; if populated at mount rather than on first user navigation, screen readers may announce slide positions for every card on page load. Fix: render the status node empty and write to it only in response to an explicit next/previous/swipe action.
