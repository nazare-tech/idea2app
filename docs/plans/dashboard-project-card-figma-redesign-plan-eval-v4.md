MAJOR verification "Risk-Matched Verification" / Test Strategy — the geometry acceptance ("card 430px ±2px, panel 188px ±2px") is tautological against a fixed `h-[430px]`/`h-[188px]` implementation: the bounding box reports the declared height whether or not the title/description/date overflow or get clipped, so the sole geometry gate cannot fail for the failure mode it exists to catch. Built as planned, a panel whose content overflows at some title/description length ships green. Fix: assert content containment instead — `scrollHeight <= clientHeight` on the panel, and that the date element's bounding rect is fully inside the panel rect, on the longest real title/description in the account.

MAJOR verification Plan step 5 ("skipped with an explicit reason if the authenticated account has no existing projects") — a conditionally skipped Playwright test is a silently passing test, and it is the only automated check with rendered-size coverage (the plan itself concedes class-string tests do not claim it). If the seeded account is reset, rotated, or the free-tier project allowance empties it, the geometry check disappears from CI without failing anything. Fix: have the spec create/seed a deterministic project fixture row (no generation, no credit spend) or fail loudly when the precondition is absent, rather than skipping.

MAJOR premises "Exact Figma panel math" — the numbers are internally inconsistent: 238px preview region minus 40px padding leaves 198px, but the media canvas is specified as `h-full max-h-[216px]`, so the 216px cap can never bind. The planned test ("assertions for the padded, 216px-capped media layout") and the wide-card acceptance row ("216px-capped image centered") assert a constraint that is dead code, and the real vertical limit (198px) is never verified. Fix: reconcile to one number — either raise the preview region or set the cap to the actual available 198px — and assert the binding constraint.

MAJOR architecture "Ownership, Scope, And Lifetime" — the plan verifies that `DashboardProjectCard` has one caller but makes no equivalent claim for `ProjectCardThumbnail`, whose padding and media sizing it changes. If that component is also used outside `/projects` (mockups grid, workspace preview), the redesign leaks into surfaces with no Figma reference and no verification step. Fix: state the caller set for `ProjectCardThumbnail`; if it has more than one, move the padding/cap into a card-owned wrapper or a prop-gated variant. I would need `src/components/**/project-card-thumbnail.tsx` and its import sites to settle this.

MAJOR premises "Exact Figma panel math" / `justify-between` — the spec simultaneously requires an 8px gap between title and description and `justify-between` ownership of ~26px of slack across three children; `justify-between` distributes that slack into *both* inter-item gaps, so the title-to-description gap renders at ~21px, not 8px, and the spacing math will not reproduce the Figma node. Fix: wrap title+description in a flex column with the explicit 8px gap and push the date down with `mt-auto`, dropping `justify-between`.

MAJOR product / premises "Rejected: changing fixed Figma pixel dimensions to rem/min-height" — fixed `px` type inside a fixed 188px panel means a user browser font-size preference (not zoom, which the rebuttal addresses) either has no effect or, where inherited sizing survives, overflows a panel with no `min-height` escape. Built as written, the card is the one surface on the dashboard that ignores user text-size settings. Fix: keep the pixel geometry but use `min-h-[430px]`/`min-h-[188px]` so overflow grows rather than clips; this still measures 430/188 for the default case the geometry gate checks.

MINOR runtime "Failure And Recovery" / narrow widths — the card height stays 430px below `sm` while the card goes full-width, but the description clamp is fixed at four lines and the reserved block at 72px; at wide-but-short and narrow-but-tall widths the description occupies different real heights, and the plan never states which of clamp-lines or reserved-height wins. Fix: pin the description block to a fixed `h-[72px]` with `line-clamp-4` and `overflow-hidden` so the two constraints cannot disagree, and assert both at the two viewports.

MINOR product Plan step 4 / "Accepted from second evaluation: use `z-10`" — `z-10` only orders siblings within a shared stacking context; if the `<Link>` or an ancestor establishes one (transform, opacity, filter on hover), the delete trigger can fall behind the link surface. The plan verifies the click routing manually once but adds no regression guard beyond the skippable smoke test. Fix: give the shared parent `relative isolate` and make the delete-click-does-not-navigate assertion part of the non-skippable component test via an event-propagation test, not only Playwright.

MINOR product "Failure And Recovery" — adding a native `title` attribute on a `truncate`d title that already contains the full text in the DOM produces duplicated announcement in several screen readers and is unavailable to keyboard and touch users. Fix: drop the `title` attribute; truncation with full DOM text already satisfies the accessibility case the plan cites.

MINOR verification "Confirmed: Exact Figma `#c9c9c9` and `#f6f6f6` values can remain local" — no acceptance row checks contrast for the secondary/italic date text on the new `#f6f6f6` panel, which is a different background than the current card surface. A token like `text-text-secondary` (#666666) that passed on white may sit differently against the new panel and the design's tighter 14px type. Fix: add a contrast check to the verification matrix with an explicit ratio threshold for date and description text on `#f6f6f6`.

MINOR premises "Rejected with evidence: no `/projects` loading skeleton or placeholder card exists" — the search evidence is asserted but the plan never names what was searched; an App Router `loading.tsx` or a `<Suspense>` fallback in the projects page would produce a card-shaped placeholder whose height now mismatches by 430px, causing visible layout shift on every navigation to `/projects`. Fix: name the checked paths (`src/app/**/projects/loading.tsx` and the page's Suspense boundaries) in the plan, or add a step to align the fallback height.
