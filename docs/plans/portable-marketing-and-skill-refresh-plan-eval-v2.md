MAJOR runtime-and-change-impact "Failure And Recovery" / step 7 — the plan concedes global skill removal only takes effect in future sessions, yet the CI/UI replacement-router scenario smokes (step 7) run in the current session where the five legacy skills are still loaded and can be the ones actually answering the smoke. A missing route in ci-operator/ui-verification would still pass because the legacy skill silently handles it. Consequence: a routing gap ships, surfacing only after a restart when the legacy skills are already in Trash and recovery needs a manual move. Fix: verify replacement routing statically (resolve every router route to a surviving file) or in a session where the five skills are already absent, before the move.

MAJOR verification "Risk-Matched Verification" (Consolidated CI/UI routes) — deletion of `ci-watcher`/`fix-ci`/`loop-on-ci`/`run-smoke-tests`/`control-ui` is gated on scenario smokes whose live-dependency arms (real Chrome, authenticated PR) are explicitly allowed to be "reported as unverified, never simulated as success" while the removal still proceeds. Consequence: `run-smoke-tests` and `control-ui` behaviors can be removed with no positively-verified replacement, only an unproven assumption that the two routers cover them. Fix: gate each removal on a per-skill positive coverage proof; if a live arm cannot run, the corresponding legacy skill stays until it can.

MAJOR security-and-data-integrity "Rollback Or Recovery" / steps 3,7 — the sole backup for the untracked starter kit and the "recoverable" removed skills is `~/.Trash/...-<timestamp>/`. `.Trash` is a user-facing, routinely-emptied location (and can be auto-purged after 30 days), so the rollback path can silently cease to exist. Consequence: an untracked starter kit or removed global skill becomes unrecoverable after a Trash empty, with no other copy. Fix: back up to a persistent non-Trash directory outside the repo (or git-init/stash the starter kit) and verify the copy before any destructive step.

MAJOR premises "Failure And Recovery" / "Rollback Or Recovery" — recovery instructions hardcode `/Users/Mukul/.Trash/...`, contradicting the plan's own "never machine-specific" premise; the invoking environment shows a different owner (agamukul) and a non-home working root. Consequence: on any host where `$HOME` isn't `/Users/Mukul`, the move-to-Trash and restore commands target a nonexistent path and either fail or write recovery data somewhere the restore step won't find it. Fix: derive the Trash/backup base from `$HOME` at runtime and record the resolved absolute path in the artifact.

MINOR architecture-and-reuse "Boundary And Cache Semantics" — collision handling versions on filename (`-v2`,`-v3`) keyed only on same-day `<slug>`. Two genuinely distinct ideas that happen to slugify identically on one date get chained as if they were revisions of one idea. Consequence: unrelated captures are conflated into a false version history. Fix: distinguish "same idea, new revision" from "different idea, colliding slug" (e.g., append a short random/content token for distinct ideas) rather than always sequential-versioning.
